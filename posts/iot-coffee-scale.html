The problem

How much coffee is still left in the thermos? To answer that without lifting the lid, I built a scale with a NodeMCU (ESP8266), an HX711 module and a load cell. It weighs the thermos every 5 seconds and shows the level on a Grafana panel.

The weight goes straight from the ESP8266 to Grafana Loki, as a JSON log line. I didn't need an API, a database or a new server: the Loki that already stored the applications' logs now stores the coffee weight too.

This post covers the whole path: parts, wiring, Arduino IDE setup, the request to Loki, the code, tare and calibration, the dashboard and the problems that showed up along the way.

Architecture

Load cell -> HX711 -> NodeMCU (ESP8266) -> Wi-Fi -> Grafana (data source proxy) -> Loki
                                                     Grafana (dashboard)    <- LogQL -- Loki

The ESP8266 can't reach Loki, which only exists inside the cluster. It sends the weight to Grafana, which forwards the push to Loki and later reads the same data back to build the dashboard.

Parts

The project started with an Arduino reading the HX711, but the NodeMCU reads the HX711 directly and also has Wi-Fi, so the Arduino was dropped.

Wiring

There are 8 wires: 4 from the cell to the HX711 and 4 from the HX711 to the NodeMCU.

WhiteA−Signal −

HX711 → NodeMCU

Three things to watch:

  • Power the HX711 at 3.3 V, not 5 V. That way the DT logic level matches the ESP8266's.
  • Avoid D3, D4 and D8 for the HX711. These pins set the board's boot mode and can keep it from starting.
  • An inverted signal is not a defect. If the number drops when you add weight, swap the white and green wires or let the calibration fix the sign (see below).

Setting up the environment

Everything runs in Arduino IDE 2. The ESP8266 board and the HX711 library are installed by the IDE itself.

  1. In File → Preferences, paste https://arduino.esp8266.com/stable/package_esp8266com_index.json into Additional boards manager URLs.
  2. In the Boards Manager, install esp8266 by ESP8266 Community.
  3. In the Library Manager, install HX711 Arduino Library by Bogdan Necula. Other libraries with a similar name (like HX711_ADC) have a different API and the sketch won't compile with them.
  4. In Tools → Board, pick NodeMCU 1.0 (ESP-12E Module).
  5. Plug in the board and, in Tools → Port, pick the new port, named Silicon Labs CP210x USB to UART Bridge (COMx).
  6. Open the Serial Monitor at 115200.
If no new port shows up, the problem is almost always the cable: many micro-USB cables only charge. If the board shows up in Device Manager with a warning icon, the CP210x Universal Windows Driver from Silicon Labs is missing. Installing drivers requires admin rights on Windows; without them, ask IT or flash the board on another computer.

COM ports named “Standard Serial over Bluetooth link” belong to the laptop's Bluetooth, not to the board. And the strange characters at the start of the serial monitor are normal: they are ESP8266 boot messages, which use a different baud rate.

Why Loki and not an API with a database

Loki is a log database, but it stores numbers very well when they come inside a JSON line. With LogQL's unwrap operator, Grafana turns the peso (weight) field of each line into a numeric series, ready to become a chart. Since it already existed at the company for the applications' logs, the path got much shorter.

Loki directlyAPI + database
What needs to be builtNothing: just the POST from the ESPEndpoint, table, deploy
How Grafana reads itExisting Loki data source + LogQLDatabase data source + SQL
HistoryOnly for Loki's retention periodAs long as you want
Business rules (alerts, server-side tare)Live in the ESP or in GrafanaLive in the API

To know how much coffee there is right now, Loki's retention is not a problem. If history ever matters (“how many thermoses per week?”), it's worth moving to API + database.

One modeling detail: the weight goes in the line body, never in a label. Labels identify the stream (service_name="balanca", dispositivo="balanca-01") and must have few values. A weight as a label would create a new stream on every reading and weigh Loki down.

Reaching Loki through Grafana

The ESP8266 doesn't talk to Loki directly: it sends the push to Grafana, which forwards it to Loki through the data source proxy. This was needed because, in Grafana's data source, Loki's URL was an internal Kubernetes name: 

http://loki-gateway.<namespace>.svc.cluster.local:80

*.svc.cluster.local names only exist inside the cluster. Grafana, which runs in there, reaches Loki; a board on the office Wi-Fi doesn't. Instead of asking to expose Loki, I used the proxy route Grafana itself offers: 

https://<your-grafana>/api/datasources/proxy/uid/<loki-uid>/loki/api/v1/push
PieceWhere to get it
<your-grafana>The address you use in the browser
<loki-uid>In Explore, the data source "uid" inside the link; or at the end of the URL in Connections → Data sources → Loki
TokenAdministration → Users and access → Service accounts: create a service account with the Viewer role and generate a token (glsa_...)

In the test, the Viewer role was enough to write through the proxy. There was also no need to send the tenant header (X-Scope-OrgID): if the data source has one configured, Grafana adds it on its own when forwarding.

Use the token, not a username and password. Everything in the firmware can be read from the board's memory by anyone with physical access to it, and a leaked Viewer token does far less damage than an admin password.

The request

Each reading is a POST with one stream and one line. The labels go in stream, and values holds a pair: the timestamp in nanoseconds (as a string) and the log line, which here is a JSON with the weight. 

{
  "streams": [{
    "stream": { "service_name": "balanca", "dispositivo": "balanca-01" },
    "values": [[ "1793298680116673000", "{\"peso\":2.345,\"unidade\":\"kg\"}" ]]
  }]
}

Loki requires the timestamp. The ESP8266 has no real clock, so it syncs the time via NTP on startup (configTime with a.st1.ntp.br and pool.ntp.org), and the code discards the reading while the clock is not right. If the network blocks UDP port 123, nothing reaches Loki.

Before flashing the board, you can test the whole path from the laptop:

curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  "https://<your-grafana>/api/datasources/proxy/uid/<loki-uid>/loki/api/v1/push" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d "{\"streams\":[{\"stream\":{\"service_name\":\"balanca\",\"dispositivo\":\"balanca-teste\"},\"values\":[[\"$(date +%s)000000000\",\"{\\\"peso\\\":1.0}\"]]}]}"
ResponseMeaning
204Written. Loki returns no body on success
401Missing or wrong token
403The service account role doesn't allow it. Change Viewer to Editor
404Wrong Grafana address or data source UID
400 with “no org id”Loki uses tenants and the data source doesn't set one. Send X-Scope-OrgID
TimeoutThe address is not reachable from that network

The code

The sketch has about 280 lines and does one thing per function. loop() runs the cycle every 5 seconds: checks tare commands, makes sure Wi-Fi is up, reads the HX711 and sends. The full code is at the end of the post (identifiers and comments are in Portuguese).

FunctionWhat it does
conectarWifi()Connects and, if it fails, says why: network not found (wrong name or 5 GHz) or password rejected
listarRedes()Lists the networks the board sees, in quotes, so you can copy the exact name
sincronizarRelogio()Sets the time via NTP; without it Loki rejects the reading
obterTimestampNs()Builds the timestamp in nanoseconds
enviarParaLoki()Builds the JSON and does the HTTPS POST with the token
fazerTara() / calibrar()Set the zero and the factor, and save both to memory
verificarComandos()Handles the FLASH button and the serial monitor commands

The timestamp comes from gettimeofday. Seconds go first, then the microseconds with 6 digits and three zeros at the end, which gives nanoseconds without needing a 64-bit integer: 

struct timeval agora;
gettimeofday(&agora, nullptr);
snprintf(destino, tamanho, "%lu%06lu000", (unsigned long)agora.tv_sec, (unsigned long)agora.tv_usec);

The request uses HTTPClient with BearSSL's TLS client. setInsecure() accepts the certificate without validating it, which is enough for an internal test; in an exposed environment, pin the certificate fingerprint. 

clienteHttps.setInsecure();
http.begin(clienteHttps, URL_LOKI);
http.addHeader("Content-Type", "application/json");
http.addHeader("Authorization", String("Bearer ") + GRAFANA_TOKEN);
int codigo = http.POST((uint8_t*)corpo, strlen(corpo));   // 204 = written

When everything is right, the serial monitor shows one line per cycle (sample values):

Conectado. IP: 192.168.0.25
Relogio OK
Peso: 2.345 kg  (bruto 133912, fator 57104.3)
Loki: 204 OK

Tare and calibration

The HX711 doesn't return kilograms: it returns a raw number, and the weight comes from two constants. The tare is the offset, the raw number with the scale empty. The calibration is the factor, how many raw units are worth 1 kg. 

weight (kg) = (reading - offset) / factor

In the library, tare() measures the offset, set_scale() sets the factor, get_value() returns reading − offset and get_units() already divides by the factor.

This is where I got it wrong before getting it right. The first readings looked like negative grams, and the first idea was to divide by −1000. A full 350 ml can, about 0.37 kg, showed up as 0.003 kg. The problem was the factor: the -7050 in the code was a sample value from a tutorial, not my cell's. Each cell has its own factor, and the right way is to measure it: 

void calibrar(float pesoRealKg) {
  double leitura = balanca.get_value(20);    // average of 20 readings, already without the tare
  balanca.set_scale(leitura / pesoRealKg);   // the factor's sign comes out right on its own
  gravarCalibracao();
}

The sketch accepts commands through the serial monitor and through the board's own FLASH button, with no extra wire:

CommandWhen to useWhat it does
t or hold FLASHEmpty scaleDoes the tare
c 1000With 1000 g on topCalculates the factor
rWrong calibration savedGoes back to the default factor and redoes the tare

Step by step, the first time:

  1. Power it on with the plate empty and type t.
  2. Put a known weight on it, preferably a sealed 1 kg package (a can's weight is less certain), and type c 1000.
  3. Remove the package and check with another object of known weight.

Offset and factor are saved in the EEPROM, together with a marker number that says the record is valid. This solves a real problem: with the tare done only at boot, a power outage with the thermos on top would zero its weight. Now the board comes back with the saved calibration, and only does the tare by itself the first time.

Two cautions: don't hold FLASH while powering the board on, because that puts it in flashing mode; and redo the tare whenever you touch the assembly.

Showing it in Grafana

The data reaches Loki as a log, and three LogQL queries solve everything. To check that it's arriving, open Explore, pick the Loki data source and run: 

{service_name="balanca", dispositivo="balanca-01"}

A new line should show up every 5 seconds, with the weight JSON. To turn it into a number, | json peso extracts the field and | unwrap peso turns it into a value:

PanelQueryType
Current weightlast_over_time({service_name="balanca", dispositivo="$dispositivo"} | json peso | unwrap peso [1m])Stat, instant query
Levelthe sameVertical bar gauge, 0 to 5 kg
History (optional)avg_over_time({service_name="balanca", dispositivo="$dispositivo"} | json peso | unwrap peso [$__interval])Time series

The final dashboard has the current weight and a wide column that rises and falls with the weight. History was left out, because the question is “how much is there now”. The column is a Bar gauge with vertical orientation and colors by weight range (red, yellow, green). The [1m] window makes the panel show “No reading” when the scale goes more than a minute without sending, which gives away a board that is off or offline.

The dashboard is an importable JSON (Dashboards → New → Import), with two variables: the Loki data source and dispositivo (device), filled with the label values (label_values({service_name="balanca"}, dispositivo)). With more than one scale, just change DISPOSITIVO in each one's sketch.

Since the scale weighs thermos + coffee, the empty thermos already takes up part of the bar. For the bar to go from “empty” to “full”, set the panel's minimum and maximum to the weight of the empty and the full thermos.

Problems we ran into

Almost none of the problems were in the code: cable, driver, network and calibration took more time than the sketch.

Next steps

  • Over-the-air updates (OTA). After the first flash by cable, the next ones would go over the network, without depending on cable and driver.
  • Filter the pump press. Whoever pours coffee pushes the thermos down, and the reading at that moment is not valid. Readings above the full thermos weight can be discarded on the ESP.
  • Coffee-running-out alert. A Grafana rule for when the weight gets close to the empty thermos weight.
  • Validate the certificate. Replace setInsecure() with the Grafana certificate fingerprint.

Full code

Change the uppercase values in the configuration block before flashing. The rest works as is.

// Balanca: celula de carga -> HX711 -> NodeMCU (ESP8266) -> Wi-Fi -> Grafana (proxy) -> Loki
// Placa: "NodeMCU 1.0 (ESP-12E Module)" | Biblioteca: "HX711 Arduino Library" (Bogdan Necula)
// Ligacao: HX711 VCC->3V3, GND->GND, DT->D5, SCK->D6

#include <ESP8266WiFi.h>
#include <ESP8266HTTPClient.h>
#include <WiFiClientSecureBearSSL.h>
#include <time.h>
#include <sys/time.h>
#include <EEPROM.h>
#include "HX711.h"

// ===================== Configuracao =====================
const char* WIFI_SSID = "SEU_WIFI";   // rede de 2,4 GHz
const char* WIFI_SENHA = "SUA_SENHA";

// Push pelo proxy de data source do Grafana, que repassa para o Loki interno do cluster
// Formato: https://<grafana>/api/datasources/proxy/uid/<uid do data source Loki>/loki/api/v1/push
const char* URL_LOKI = "https://SEU_GRAFANA/api/datasources/proxy/uid/UID_DO_LOKI/loki/api/v1/push";

// Autenticacao no Grafana: prefira o token de service account; o usuario/senha so e usado sem token
const char* GRAFANA_TOKEN = "glsa_SEU_TOKEN";   // Administration > Users and access > Service accounts > Add token
const char* GRAFANA_USUARIO = "";
const char* GRAFANA_SENHA = "";
const char* LOKI_TENANT = "";   // header X-Scope-OrgID, so se o Loki for multi-tenant

// Labels do stream no Loki (mantenha fixos: o peso vai na linha, nunca em label)
const char* SERVICO = "balanca";
const char* DISPOSITIVO = "balanca-01";

const int PINO_DT = D5;
const int PINO_SCK = D6;
const float FATOR_CALIBRACAO = -7050.0f;   // so vale ate calibrar pelo monitor serial ("c <gramas>"); depois fica gravado na placa
const int PINO_BOTAO_TARA = 0;             // botao FLASH da propria NodeMCU
const int LEITURAS_POR_MEDIA = 10;
const unsigned long INTERVALO_ENVIO_MS = 5000;
// ========================================================

HX711 balanca;
WiFiClient clienteHttp;
BearSSL::WiFiClientSecure clienteHttps;
unsigned long ultimoEnvio = 0;

void conectarWifi() {
  if (WiFi.status() == WL_CONNECTED) {
    return;
  }

  Serial.printf("Conectando ao WiFi %s", WIFI_SSID);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_SENHA);

  unsigned long inicio = millis();
  while (WiFi.status() != WL_CONNECTED && millis() - inicio < 20000) {
    delay(500);
    Serial.print(".");
  }

  if (WiFi.status() == WL_CONNECTED) {
    Serial.printf("\nConectado. IP: %s\n", WiFi.localIP().toString().c_str());
    return;
  }

  wl_status_t status = WiFi.status();
  if (status == WL_NO_SSID_AVAIL) {
    Serial.println("\nFalha no WiFi: rede nao encontrada (nome diferente ou rede 5 GHz)");
  } else if (status == WL_WRONG_PASSWORD || status == WL_CONNECT_FAILED) {
    Serial.println("\nFalha no WiFi: senha recusada");
  } else {
    Serial.printf("\nFalha no WiFi (status %d), tento de novo no proximo ciclo\n", status);
  }
  listarRedes();
}

// Mostra as redes que a placa enxerga (o ESP8266 so ve redes 2,4 GHz)
void listarRedes() {
  int total = WiFi.scanNetworks();
  Serial.printf("Redes visiveis: %d\n", total);
  for (int i = 0; i < total; i++) {
    Serial.printf("  \"%s\" sinal %d dBm\n", WiFi.SSID(i).c_str(), WiFi.RSSI(i));
  }
  WiFi.scanDelete();
}

// O Loki exige timestamp real (epoch em nanossegundos), por isso o relogio vem do NTP
void sincronizarRelogio() {
  configTime(0, 0, "a.st1.ntp.br", "pool.ntp.org");
  Serial.print("Sincronizando relogio (NTP)");

  unsigned long inicio = millis();
  while (time(nullptr) < 1700000000 && millis() - inicio < 20000) {
    delay(500);
    Serial.print(".");
  }

  Serial.println(time(nullptr) < 1700000000 ? "\nNTP sem resposta (porta UDP 123 bloqueada?)" : "\nRelogio OK");
}

bool obterTimestampNs(char* destino, size_t tamanho) {
  struct timeval agora;
  gettimeofday(&agora, nullptr);
  if (agora.tv_sec < 1700000000) {
    return false;
  }

  snprintf(destino, tamanho, "%lu%06lu000", (unsigned long)agora.tv_sec, (unsigned long)agora.tv_usec);
  return true;
}

void enviarParaLoki(float peso) {
  char timestamp[24];
  if (!obterTimestampNs(timestamp, sizeof(timestamp))) {
    Serial.println("Relogio ainda sem NTP, leitura descartada");
    sincronizarRelogio();
    return;
  }

  char corpo[320];
  snprintf(corpo, sizeof(corpo),
    "{\"streams\":[{\"stream\":{\"service_name\":\"%s\",\"dispositivo\":\"%s\"},"
    "\"values\":[[\"%s\",\"{\\\"peso\\\":%.3f,\\\"unidade\\\":\\\"kg\\\"}\"]]}]}",
    SERVICO, DISPOSITIVO, timestamp, peso);

  bool usaHttps = strncmp(URL_LOKI, "https", 5) == 0;
  HTTPClient http;
  http.setTimeout(5000);
  if (usaHttps) {
    clienteHttps.setInsecure();   // sem validar certificado; em producao fixe o fingerprint
    http.begin(clienteHttps, URL_LOKI);
  } else {
    http.begin(clienteHttp, URL_LOKI);
  }

  http.addHeader("Content-Type", "application/json");
  if (strlen(GRAFANA_TOKEN) > 0) {
    http.addHeader("Authorization", String("Bearer ") + GRAFANA_TOKEN);
  } else if (strlen(GRAFANA_USUARIO) > 0) {
    http.setAuthorization(GRAFANA_USUARIO, GRAFANA_SENHA);
  }
  if (strlen(LOKI_TENANT) > 0) {
    http.addHeader("X-Scope-OrgID", LOKI_TENANT);
  }

  int codigo = http.POST((uint8_t*)corpo, strlen(corpo));
  if (codigo == 204) {
    Serial.println("Loki: 204 OK");
  } else {
    Serial.printf("Loki: %d %s\n", codigo, codigo > 0 ? http.getString().c_str() : http.errorToString(codigo).c_str());
    if (codigo == 401 || codigo == 403) {
      Serial.println("  -> Grafana recusou a credencial: confira o token e o papel da service account");
    } else if (codigo == 404) {
      Serial.println("  -> Caminho nao existe: confira o endereco do Grafana e o UID do Loki na URL_LOKI");
    }
  }
  http.end();
}

// Tara (zero) e fator gravados na memoria da placa: sobrevivem a queda de energia com a garrafa em cima
struct CalibracaoGravada {
  uint32_t marca;
  long offset;
  float fator;
};
const uint32_t MARCA_CALIBRACAO = 0xBA1A0002;

void gravarCalibracao() {
  CalibracaoGravada calibracao = { MARCA_CALIBRACAO, balanca.get_offset(), balanca.get_scale() };
  EEPROM.put(0, calibracao);
  EEPROM.commit();
}

bool carregarCalibracao() {
  CalibracaoGravada calibracao;
  EEPROM.get(0, calibracao);
  if (calibracao.marca != MARCA_CALIBRACAO) {
    return false;
  }

  balanca.set_offset(calibracao.offset);
  balanca.set_scale(calibracao.fator);
  Serial.printf("Calibracao carregada da memoria (fator %.1f)\n", calibracao.fator);
  return true;
}

void fazerTara() {
  Serial.println("Fazendo tara, deixe a balanca vazia...");
  balanca.tare(20);
  gravarCalibracao();
  Serial.println("Tara feita e gravada");
}

// Com um peso conhecido em cima, calcula o fator que transforma a leitura do HX711 em kg (o sinal sai certo sozinho)
void calibrar(float pesoRealKg) {
  Serial.printf("Calibrando com %.3f kg em cima...\n", pesoRealKg);
  double leitura = balanca.get_value(20);
  if (fabs(leitura) < 100) {
    Serial.println("Leitura quase zero: o peso esta em cima? Faca a tara com a balanca vazia antes");
    return;
  }

  balanca.set_scale(leitura / pesoRealKg);
  gravarCalibracao();
  Serial.printf("Calibrado e gravado (fator %.1f). Peso agora: %.3f kg\n", balanca.get_scale(), balanca.get_units(10));
}

// Comandos: botao FLASH ou "t" = tara; "c <gramas>" = calibrar com peso conhecido (ex.: c 1000); "r" = apagar a calibracao
void verificarComandos() {
  bool pediuTara = digitalRead(PINO_BOTAO_TARA) == LOW;
  if (Serial.available() > 0) {
    String comando = Serial.readStringUntil('\n');
    comando.trim();
    if (comando.equalsIgnoreCase("t")) {
      pediuTara = true;
    } else if (comando.equalsIgnoreCase("r")) {
      Serial.println("Apagando a calibracao gravada e voltando ao fator padrao");
      balanca.set_scale(FATOR_CALIBRACAO);
      pediuTara = true;
    } else if (comando.startsWith("c") || comando.startsWith("C")) {
      float gramas = comando.substring(1).toFloat();
      if (gramas > 0) {
        calibrar(gramas / 1000.0f);
      } else {
        Serial.println("Use: c <peso em gramas>, ex.: c 1000");
      }
    }
  }

  if (!pediuTara) {
    return;
  }

  fazerTara();
  while (digitalRead(PINO_BOTAO_TARA) == LOW) {
    delay(10);
  }
}

void setup() {
  Serial.begin(115200);
  delay(200);
  Serial.println("\nBalanca ESP8266 -> Loki");

  EEPROM.begin(sizeof(CalibracaoGravada));
  pinMode(PINO_BOTAO_TARA, INPUT_PULLUP);

  balanca.begin(PINO_DT, PINO_SCK);
  balanca.set_scale(FATOR_CALIBRACAO);
  if (!carregarCalibracao()) {
    fazerTara();   // primeira vez: a balanca precisa estar VAZIA
    Serial.println("Ainda sem calibracao: coloque um peso conhecido e digite c <gramas>, ex.: c 1000");
  }

  conectarWifi();
  sincronizarRelogio();
}

void loop() {
  verificarComandos();

  if (millis() - ultimoEnvio < INTERVALO_ENVIO_MS) {
    return;
  }
  ultimoEnvio = millis();

  conectarWifi();
  if (WiFi.status() != WL_CONNECTED) {
    return;
  }

  if (!balanca.wait_ready_timeout(1000)) {
    Serial.println("HX711 nao respondeu, confira DT/SCK e a alimentacao");
    return;
  }

  double bruto = balanca.get_value(LEITURAS_POR_MEDIA);   // leitura do HX711 menos a tara; tem que mudar quando poe peso
  float peso = bruto / balanca.get_scale();
  Serial.printf("Peso: %.3f kg  (bruto %.0f, fator %.1f)\n", peso, bruto, balanca.get_scale());

  enviarParaLoki(peso);
}

O problema

Quanto café ainda tem na garrafa térmica? Para responder isso sem levantar a tampa, montei uma balança com um NodeMCU (ESP8266), um módulo HX711 e uma célula de carga. Ela pesa a garrafa a cada 5 segundos e mostra o nível num painel do Grafana.

O peso vai direto do ESP8266 para o Grafana Loki, como uma linha de log em JSON. Não precisei de API, banco de dados nem servidor novo: o Loki que já guardava os logs das aplicações passou a guardar também o peso do café.

Neste post está o caminho completo: componentes, ligações, preparação da Arduino IDE, o request para o Loki, o código, a tara e a calibração, o dashboard e os problemas que apareceram no caminho.

Arquitetura

Célula de carga -> HX711 -> NodeMCU (ESP8266) -> Wi-Fi -> Grafana (proxy de data source) -> Loki
                                                           Grafana (dashboard)    <- LogQL -- Loki

O ESP8266 não alcança o Loki, que só existe dentro do cluster. Ele envia o peso ao Grafana, que repassa o push ao Loki e depois lê o mesmo dado para montar o dashboard.

Componentes

O projeto começou com um Arduino lendo o HX711, mas o NodeMCU lê o HX711 direto e ainda tem Wi-Fi, então o Arduino saiu da montagem.

Três cuidados:

  • Alimente o HX711 em 3,3 V, não em 5 V. Assim o nível lógico do DT bate com o do ESP8266.
  • Evite D3, D4 e D8 para o HX711. Esses pinos definem o modo de boot da placa e podem impedir que ela ligue.
  • Sinal invertido não é defeito. Se o número cai quando você põe peso, troque o branco com o verde ou deixe a calibração resolver o sinal (mais abaixo).

Preparando o ambiente

Tudo roda na Arduino IDE 2. A placa ESP8266 e a biblioteca do HX711 são instaladas pela própria IDE.

  1. Em Arquivo → Preferências, no campo URLs adicionais do Gerenciador de Placas, cole https://arduino.esp8266.com/stable/package_esp8266com_index.json.
  2. No Gerenciador de Placas, instale esp8266 by ESP8266 Community.
  3. No Gerenciador de Bibliotecas, instale HX711 Arduino Library by Bogdan Necula. Outras bibliotecas com nome parecido (como a HX711_ADC) têm outra API e o sketch não compila com elas.
  4. Em Ferramentas → Placa, escolha NodeMCU 1.0 (ESP-12E Module).
  5. Plugue a placa e escolha em Ferramentas → Porta a porta que apareceu, chamada Silicon Labs CP210x USB to UART Bridge (COMx).
  6. Abra o Monitor Serial em 115200.
Se nenhuma porta nova aparecer, o problema quase sempre é o cabo: muitos cabos micro-USB só carregam. Se a placa aparecer no Gerenciador de Dispositivos com um ícone de alerta, falta o driver CP210x Universal Windows Driver da Silicon Labs. Instalar driver exige administrador no Windows; sem essa permissão, peça à TI ou grave a placa em outro computador.

Portas COM chamadas “Serial Padrão por link Bluetooth” são do Bluetooth do notebook, não da placa. E os caracteres estranhos no início do monitor serial são normais: são mensagens do boot do ESP8266, que usam outra velocidade.

Por que Loki e não uma API com banco

O Loki é um banco de logs, mas guarda números muito bem quando eles vêm dentro de uma linha em JSON. Com o operador unwrap da LogQL, o Grafana transforma o campo peso de cada linha numa série numérica, pronta para virar gráfico. Como ele já existia na empresa para os logs das aplicações, o caminho ficou bem mais curto.

Loki diretoAPI + banco
O que precisa criarNada: só o POST do ESPEndpoint, tabela, deploy
Como o Grafana lêData source Loki já existente + LogQLData source do banco + SQL
HistóricoSó pelo período de retenção do LokiPelo tempo que quiser
Regras de negócio (alerta, tara no servidor)Ficam no ESP ou no GrafanaFicam na API

Para saber quanto café tem agora, a retenção do Loki não é problema. Se um dia o histórico importar (“quantas garrafas por semana?”), vale migrar para API + banco.

Um cuidado de modelagem: o peso vai no corpo da linha, nunca em label. Labels identificam o stream (service_name="balanca", dispositivo="balanca-01") e precisam ter poucos valores. Um peso como label criaria um stream novo a cada leitura e pesaria no Loki.

Chegando no Loki pelo Grafana

O ESP8266 não fala com o Loki direto: ele manda o push para o Grafana, que repassa ao Loki pelo proxy de data source. Isso foi necessário porque, na fonte de dados do Grafana, a URL do Loki era um nome interno do Kubernetes: 

http://loki-gateway.<namespace>.svc.cluster.local:80

Nomes *.svc.cluster.local só existem dentro do cluster. O Grafana, que roda lá dentro, alcança o Loki; uma placa no Wi-Fi do escritório, não. Em vez de pedir para expor o Loki, usei a rota de proxy que o próprio Grafana oferece: 

https://<seu-grafana>/api/datasources/proxy/uid/<uid-do-loki>/loki/api/v1/push
PeçaOnde pegar
<seu-grafana>O endereço que você usa no navegador
<uid-do-loki>No Explore, o "uid" da fonte de dados dentro do link; ou no final da URL de Connections → Data sources → Loki
TokenAdministration → Users and access → Service accounts: crie uma service account com papel Viewer e gere um token (glsa_...)

No teste, o papel Viewer foi suficiente para gravar pelo proxy. Também não foi preciso mandar o header de tenant (X-Scope-OrgID): se a fonte de dados tiver um configurado, o Grafana o acrescenta sozinho no repasse.

Use o token, não usuário e senha. Tudo o que está no firmware pode ser lido da memória da placa por quem tiver acesso físico a ela, e um token de Viewer exposto causa muito menos estrago que a senha de um admin.

O request

Cada leitura é um POST com um stream e uma linha. Os labels ficam em stream, e em values vai um par: o timestamp em nanossegundos (como string) e a linha de log, que aqui é um JSON com o peso. 

{
  "streams": [{
    "stream": { "service_name": "balanca", "dispositivo": "balanca-01" },
    "values": [[ "1793298680116673000", "{\"peso\":2.345,\"unidade\":\"kg\"}" ]]
  }]
}

O Loki exige o timestamp. O ESP8266 não tem relógio de verdade, então ele sincroniza a hora por NTP ao ligar (configTime com a.st1.ntp.br e pool.ntp.org), e o código descarta a leitura enquanto o relógio não estiver certo. Se a rede bloquear a porta UDP 123, nada chega ao Loki.

Antes de gravar a placa, dá para testar o caminho inteiro pelo notebook:

curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  "https://<seu-grafana>/api/datasources/proxy/uid/<uid-do-loki>/loki/api/v1/push" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d "{\"streams\":[{\"stream\":{\"service_name\":\"balanca\",\"dispositivo\":\"balanca-teste\"},\"values\":[[\"$(date +%s)000000000\",\"{\\\"peso\\\":1.0}\"]]}]}"
RespostaSignificado

403O papel da service account não permite. Troque Viewer por Editor

O código

O sketch tem cerca de 280 linhas e faz uma coisa por função. O loop() roda o ciclo a cada 5 segundos: confere comandos de tara, garante o Wi-Fi, lê o HX711 e envia. O código completo está no fim do post.

O timestamp sai de gettimeofday. Os segundos ficam na frente, os microssegundos com 6 dígitos e três zeros no fim, o que dá nanossegundos sem precisar de inteiro de 64 bits:

O envio usa o HTTPClient com o cliente TLS do BearSSL. O setInsecure() aceita o certificado sem validar, o que basta para um teste interno; num ambiente exposto, fixe o fingerprint do certificado.

http.addHeader("Authorization", String("Bearer ") + GRAFANA_TOKEN);

Com tudo certo, o monitor serial mostra uma linha por ciclo (valores de exemplo):

Peso: 2.345 kg  (bruto 133912, fator 57104.3)
Loki: 204 OK

Tara e calibração

O HX711 não devolve quilos: devolve um número cru, e o peso sai de duas constantes. A tara é o offset, o número cru com a balança vazia. A calibração é o fator, quantas unidades cruas valem 1 kg. 

peso (kg) = (leitura - offset) / fator

Na biblioteca, tare() mede o offset, set_scale() define o fator, get_value() devolve leitura − offset e get_units() já divide pelo fator.

Aqui eu errei antes de acertar. As primeiras leituras pareciam gramas com sinal negativo, e a primeira ideia foi dividir por −1000. Uma lata de 350 ml cheia, com uns 0,37 kg, apareceu como 0,003 kg. O problema era o fator: o -7050 do código era um valor de exemplo de tutorial, não o da minha célula. Cada célula tem o seu fator, e o jeito certo é medir: 

void calibrar(float pesoRealKg) {
  double leitura = balanca.get_value(20);    // média de 20 leituras, já sem a tara
  balanca.set_scale(leitura / pesoRealKg);   // o sinal do fator sai certo sozinho
  gravarCalibracao();
}

O sketch aceita comandos pelo monitor serial e pelo botão FLASH da própria placa, sem fio extra:

ComandoQuando usarO que faz
t ou segurar o FLASHBalança vaziaFaz a tara
c 1000Com 1000 g em cimaCalcula o fator
rCalibração errada gravadaVolta ao fator padrão e refaz a tara

O passo a passo da primeira vez:

  1. Ligue com o prato vazio e digite t.
  2. Coloque um peso conhecido, de preferência um pacote fechado de 1 kg (lata tem peso mais incerto), e digite c 1000.
  3. Tire o pacote e confira com outro objeto de peso conhecido.

Offset e fator ficam gravados na EEPROM, junto com um número-marca que indica que a gravação é válida. Isso resolve um problema real: com a tara feita só no boot, uma queda de energia com a garrafa em cima zeraria o peso dela. Agora a placa religa com a calibração gravada, e só faz a tara sozinha na primeira vez.

Dois cuidados: não segure o FLASH na hora de ligar a placa, porque isso a coloca em modo de gravação; e refaça a tara sempre que mexer na montagem.

Mostrando no Grafana

O dado chega no Loki como log, e três queries LogQL resolvem tudo. Para conferir se está chegando, abra o Explore, escolha a fonte de dados Loki e rode: 

{service_name="balanca", dispositivo="balanca-01"}

Deve aparecer uma linha nova a cada 5 segundos, com o JSON do peso. Para virar número, | json peso extrai o campo e | unwrap peso transforma em valor:

PainelQueryTipo

O dashboard final tem o peso atual e uma coluna larga que sobe e desce com o peso. O histórico ficou de fora, porque a pergunta é “quanto tem agora”. A coluna é um Bar gauge com orientação vertical e cores por faixa de peso (vermelho, amarelo, verde). A janela [1m] faz o painel mostrar “Sem leitura” quando a balança fica mais de um minuto sem enviar, o que denuncia placa desligada ou sem rede.

O dashboard é um JSON importável (Dashboards → New → Import), com duas variáveis: a fonte de dados Loki e o dispositivo, preenchido com os valores do label (label_values({service_name="balanca"}, dispositivo)). Com mais de uma balança, basta mudar o DISPOSITIVO no sketch de cada uma.

Como a balança pesa garrafa + café, a garrafa vazia já ocupa um pedaço da barra. Para a barra ir de “vazia” a “cheia”, ajuste o mínimo e o máximo do painel para o peso da garrafa vazia e da garrafa cheia.

// Push pelo proxy de data source do Grafana, que repassa para o Loki interno do cluster
// Formato: https://<grafana>/api/datasources/proxy/uid/<uid do data source Loki>/loki/api/v1/push
const char* URL_LOKI = "https://SEU_GRAFANA/api/datasources/proxy/uid/UID_DO_LOKI/loki/api/v1/push";

// Autenticacao no Grafana: prefira o token de service account; o usuario/senha so e usado sem token

// Labels do stream no Loki (mantenha fixos: o peso vai na linha, nunca em label)

void conectarWifi() {
  if (WiFi.status() == WL_CONNECTED) {
    return;
  }

  Serial.printf("Conectando ao WiFi %s", WIFI_SSID);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_SENHA);

  unsigned long inicio = millis();
  while (WiFi.status() != WL_CONNECTED && millis() - inicio < 20000) {
    delay(500);
    Serial.print(".");
  }

  if (WiFi.status() == WL_CONNECTED) {
    Serial.printf("\nConectado. IP: %s\n", WiFi.localIP().toString().c_str());
    return;
  }

  wl_status_t status = WiFi.status();
  if (status == WL_NO_SSID_AVAIL) {
    Serial.println("\nFalha no WiFi: rede nao encontrada (nome diferente ou rede 5 GHz)");
  } else if (status == WL_WRONG_PASSWORD || status == WL_CONNECT_FAILED) {
    Serial.println("\nFalha no WiFi: senha recusada");
  } else {
    Serial.printf("\nFalha no WiFi (status %d), tento de novo no proximo ciclo\n", status);
  }
  listarRedes();
}

// Mostra as redes que a placa enxerga (o ESP8266 so ve redes 2,4 GHz)
void listarRedes() {
  int total = WiFi.scanNetworks();

}

// O Loki exige timestamp real (epoch em nanossegundos), por isso o relogio vem do NTP
void sincronizarRelogio() {
  configTime(0, 0, "a.st1.ntp.br", "pool.ntp.org");
  Serial.print("Sincronizando relogio (NTP)");

  unsigned long inicio = millis();
  while (time(nullptr) < 1700000000 && millis() - inicio < 20000) {
    delay(500);
    Serial.print(".");
  }

  Serial.println(time(nullptr) < 1700000000 ? "\nNTP sem resposta (porta UDP 123 bloqueada?)" : "\nRelogio OK");
}

bool obterTimestampNs(char* destino, size_t tamanho) {
  struct timeval agora;
  gettimeofday(&agora, nullptr);
  if (agora.tv_sec < 1700000000) {
    return false;
  }

  snprintf(destino, tamanho, "%lu%06lu000", (unsigned long)agora.tv_sec, (unsigned long)agora.tv_usec);
  return true;
}

void enviarParaLoki(float peso) {
  char timestamp[24];
  if (!obterTimestampNs(timestamp, sizeof(timestamp))) {
    Serial.println("Relogio ainda sem NTP, leitura descartada");
    sincronizarRelogio();
    return;
  }

  char corpo[320];
  snprintf(corpo, sizeof(corpo),
    "{\"streams\":[{\"stream\":{\"service_name\":\"%s\",\"dispositivo\":\"%s\"},"
    "\"values\":[[\"%s\",\"{\\\"peso\\\":%.3f,\\\"unidade\\\":\\\"kg\\\"}\"]]}]}",
    SERVICO, DISPOSITIVO, timestamp, peso);

  bool usaHttps = strncmp(URL_LOKI, "https", 5) == 0;
  HTTPClient http;
  http.setTimeout(5000);
  if (usaHttps) {
    clienteHttps.setInsecure();   // sem validar certificado; em producao fixe o fingerprint
    http.begin(clienteHttps, URL_LOKI);
  } else {
    http.begin(clienteHttp, URL_LOKI);
  }

  http.addHeader("Content-Type", "application/json");
  if (strlen(GRAFANA_TOKEN) > 0) {
    http.addHeader("Authorization", String("Bearer ") + GRAFANA_TOKEN);
  } else if (strlen(GRAFANA_USUARIO) > 0) {
    http.setAuthorization(GRAFANA_USUARIO, GRAFANA_SENHA);
  }
  if (strlen(LOKI_TENANT) > 0) {
    http.addHeader("X-Scope-OrgID", LOKI_TENANT);
  }

  int codigo = http.POST((uint8_t*)corpo, strlen(corpo));
  if (codigo == 204) {
    Serial.println("Loki: 204 OK");
  } else {
    Serial.printf("Loki: %d %s\n", codigo, codigo > 0 ? http.getString().c_str() : http.errorToString(codigo).c_str());
    if (codigo == 401 || codigo == 403) {
      Serial.println("  -> Grafana recusou a credencial: confira o token e o papel da service account");
    } else if (codigo == 404) {
      Serial.println("  -> Caminho nao existe: confira o endereco do Grafana e o UID do Loki na URL_LOKI");
    }
  }
  http.end();
}

// Tara (zero) e fator gravados na memoria da placa: sobrevivem a queda de energia com a garrafa em cima
struct CalibracaoGravada {
  uint32_t marca;
  long offset;
  float fator;
};
const uint32_t MARCA_CALIBRACAO = 0xBA1A0002;

void gravarCalibracao() {
  CalibracaoGravada calibracao = { MARCA_CALIBRACAO, balanca.get_offset(), balanca.get_scale() };
  EEPROM.put(0, calibracao);
  EEPROM.commit();
}

bool carregarCalibracao() {
  CalibracaoGravada calibracao;
  EEPROM.get(0, calibracao);
  if (calibracao.marca != MARCA_CALIBRACAO) {
    return false;
  }

  balanca.set_offset(calibracao.offset);
  balanca.set_scale(calibracao.fator);
  Serial.printf("Calibracao carregada da memoria (fator %.1f)\n", calibracao.fator);
  return true;
}

void fazerTara() {
  Serial.println("Fazendo tara, deixe a balanca vazia...");
  balanca.tare(20);
  gravarCalibracao();
  Serial.println("Tara feita e gravada");
}

// Com um peso conhecido em cima, calcula o fator que transforma a leitura do HX711 em kg (o sinal sai certo sozinho)
void calibrar(float pesoRealKg) {
  Serial.printf("Calibrando com %.3f kg em cima...\n", pesoRealKg);
  double leitura = balanca.get_value(20);
  if (fabs(leitura) < 100) {
    Serial.println("Leitura quase zero: o peso esta em cima? Faca a tara com a balanca vazia antes");
    return;
  }

  balanca.set_scale(leitura / pesoRealKg);
  gravarCalibracao();
  Serial.printf("Calibrado e gravado (fator %.1f). Peso agora: %.3f kg\n", balanca.get_scale(), balanca.get_units(10));
}

// Comandos: botao FLASH ou "t" = tara; "c <gramas>" = calibrar com peso conhecido (ex.: c 1000); "r" = apagar a calibracao
void verificarComandos() {
  bool pediuTara = digitalRead(PINO_BOTAO_TARA) == LOW;
  if (Serial.available() > 0) {
    String comando = Serial.readStringUntil('\n');
    comando.trim();
    if (comando.equalsIgnoreCase("t")) {
      pediuTara = true;
    } else if (comando.equalsIgnoreCase("r")) {
      Serial.println("Apagando a calibracao gravada e voltando ao fator padrao");
      balanca.set_scale(FATOR_CALIBRACAO);
      pediuTara = true;
    } else if (comando.startsWith("c") || comando.startsWith("C")) {
      float gramas = comando.substring(1).toFloat();
      if (gramas > 0) {
        calibrar(gramas / 1000.0f);
      } else {
        Serial.println("Use: c <peso em gramas>, ex.: c 1000");
      }
    }
  }

  if (!pediuTara) {
    return;
  }

  fazerTara();
  while (digitalRead(PINO_BOTAO_TARA) == LOW) {
    delay(10);
  }
}

void setup() {
  Serial.begin(115200);
  delay(200);
  Serial.println("\nBalanca ESP8266 -> Loki");

  EEPROM.begin(sizeof(CalibracaoGravada));
  pinMode(PINO_BOTAO_TARA, INPUT_PULLUP);

  balanca.begin(PINO_DT, PINO_SCK);
  balanca.set_scale(FATOR_CALIBRACAO);
  if (!carregarCalibracao()) {
    fazerTara();   // primeira vez: a balanca precisa estar VAZIA
    Serial.println("Ainda sem calibracao: coloque um peso conhecido e digite c <gramas>, ex.: c 1000");
  }

  conectarWifi();
  sincronizarRelogio();
}

void loop() {
  verificarComandos();

  if (millis() - ultimoEnvio < INTERVALO_ENVIO_MS) {
    return;
  }
  ultimoEnvio = millis();

  conectarWifi();
  if (WiFi.status() != WL_CONNECTED) {
    return;
  }

  if (!balanca.wait_ready_timeout(1000)) {
    Serial.println("HX711 nao respondeu, confira DT/SCK e a alimentacao");
    return;
  }

  double bruto = balanca.get_value(LEITURAS_POR_MEDIA);   // leitura do HX711 menos a tara; tem que mudar quando poe peso
  float peso = bruto / balanca.get_scale();
  Serial.printf("Peso: %.3f kg  (bruto %.0f, fator %.1f)\n", peso, bruto, balanca.get_scale());

  enviarParaLoki(peso);
}
